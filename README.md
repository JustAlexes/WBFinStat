# FinStat

Первый шаблон веб-приложения для финансовых отчётов Wildberries. Сервер написан на Django 5.2, локальные данные хранятся в SQLite.

## Первый запуск

Нужен Python 3.10 или новее. Откройте терминал в папке репозитория.

### Windows (PowerShell)

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver
```

Откройте http://127.0.0.1:8000/ в браузере. Для остановки сервера нажмите `Ctrl+C`.

Команда `migrate` создаёт локальную базу `db.sqlite3`. Файл базы и виртуальное окружение `.venv` не отправляются в GitHub.

В интерфейсе есть главная страница, сворачиваемое боковое меню и демонстрационный профиль. В меню пользователя находятся ссылки на профиль и настройки. В настройках можно выбрать светлую или тёмную тему; выбор сохраняется в браузере.

## Данные Wildberries

Создайте файл `.env` рядом с `manage.py` и добавьте строку (без кавычек):

```dotenv
КОСТРИК=ваш_API_токен
```

Нужен персональный или сервисный токен Wildberries с категорией **Финансы**. Файл `.env` игнорируется Git и не должен попадать в репозиторий. Перезапустите сервер после изменения токена.

При входе главная открывается без отчётов и без запросов к Wildberries. Выберите период в календаре и нажмите «Загрузить отчёты». Используются только еженедельные отчёты. Один клик по строке выбирает неделю, второй — конец диапазона; затем нажмите «Выбрать период». Неделя на границе месяца разделена на отдельные отрезки: например, 26–31 октября и 1 ноября. Сервер разрешает начало в понедельник или первый день месяца и конец в воскресенье или последний день месяца. Незавершённые отрезки в календаре недоступны. Есть быстрый выбор последней завершённой недели и прошлого месяца. Результат показывается после нажатия кнопки загрузки. При новом открытии или обновлении главной снова отображается пустой экран выбора периода; старые ссылки с ID загрузки отчёты не восстанавливают. Готовая детализация каждого отчёта появляется на месте, без перезагрузки страницы. Статус проверяется раз в 10 секунд. Для каждого нового готового отчёта справа сверху показывается уведомление с номером и периодом; оно исчезает через 10 секунд. Уже готовые при открытии отчёты повторных уведомлений не вызывают. Если точно такой диапазон дат уже загружался и ответ был непустым, приложение показывает последнюю сохранённую загрузку из SQLite без запроса списка к WB. Для нового диапазона запрашивает список отчётов реализации, сохраняет полный ответ и показывает суммы. Пустой ответ не используется как постоянный кеш: отчёты могли ещё не появиться. Кнопка «Обновить из WB» явно запрашивает список заново с учётом лимита API. Полностью сохранённая детализация используется повторно; незавершённая догружается с сохранённой позиции. При повторном выборе периода после ошибки детализации загрузка возобновляется автоматически. В таблице «Продано», «Хранение», «Удержания/Выплаты» и «Штрафы» берутся напрямую из полей `retailAmountSum`, `paidStorageSum`, `deductionSum`, `penaltySum`.

Расшифровка удержаний загружается автоматически по ID каждого отчёта с ненулевой суммой, сохраняется в SQLite и группируется по причине. Старые пустые или неполные расшифровки за период автоматически заменяются при открытии выбранной загрузки. Нажатие на сумму открывает готовые группы поверх таблицы. Метод детализации выдаёт данные частями и ограничен одним запросом в минуту: пока загрузка идёт, на главной отображается статус. Держите сервер Django запущенным до завершения; при повторном выборе периода незавершённая загрузка возобновляется с сохранённого номера строки. Пока это не расчёт чистой прибыли и не детализация по товарам.

Период отчёта показывается в формате `дд.мм.гггг`, типы `1` и `2` — как «Основной» и «По выкупам». Колонки программы лояльности и «Итого к оплате» берутся из сохранённого ответа списка отчётов без дополнительных запросов к API.

Для разработки приложение запускается с `DEBUG=True`; перед размещением в интернете потребуется отдельная настройка безопасности, включая `DJANGO_SECRET_KEY`.
