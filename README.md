# FinStat

Первый шаблон веб-приложения для финансовых отчётов Wildberries. Сервер написан на Django 5.2, локальные данные хранятся в SQLite.

## Первый запуск

Нужен Python 3.10 или новее. Откройте терминал в папке репозитория.

### Windows (PowerShell)

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

### macOS / Linux

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver
```

Откройте http://127.0.0.1:8000/ в браузере. Для остановки сервера нажмите `Ctrl+C`.

Команда `migrate` создаёт локальную базу `db.sqlite3`. Файл базы и виртуальное окружение `.venv` не отправляются в GitHub.

В интерфейсе есть главная страница, сворачиваемое боковое меню и демонстрационный профиль. В меню пользователя находятся ссылки на профиль и настройки. В настройках можно выбрать светлую или тёмную тему; выбор сохраняется в браузере.

## Данные Wildberries

Создайте файл `.env` рядом с `manage.py` и добавьте строку (без кавычек):

```dotenv
КОСТРИК=ваш_API_токен
```

Нужен персональный или сервисный токен Wildberries с категорией **Финансы**. Файл `.env` игнорируется Git и не должен попадать в репозиторий. Перезапустите сервер после изменения токена.

На главной выберите даты и периодичность, затем нажмите «Загрузить отчёты». Приложение обращается к методу списка отчётов реализации, сохраняет полный ответ в локальной SQLite и показывает суммы из списка и все исходные поля каждого отчёта. В таблице «Продано», «Хранение», «Удержания/Выплаты» и «Штрафы» берутся напрямую из полей `retailAmountSum`, `paidStorageSum`, `deductionSum`, `penaltySum`.

Расшифровка удержаний загружается автоматически после списка отчётов, сохраняется в SQLite и группируется по причине. Стрелка рядом с суммой открывает готовые группы. Метод детализации выдаёт данные частями и ограничен одним запросом в минуту: пока загрузка идёт, на главной отображается статус. Держите сервер Django запущенным до завершения; при обновлении страницы незавершённая загрузка возобновляется. Пока это не расчёт чистой прибыли и не детализация по товарам.

Период отчёта показывается в формате `дд.мм.гггг`, типы `1` и `2` — как «Основной» и «По выкупам». Колонки программы лояльности и «Итого к оплате» берутся из сохранённого ответа списка отчётов без дополнительных запросов к API.

Для разработки приложение запускается с `DEBUG=True`; перед размещением в интернете потребуется отдельная настройка безопасности, включая `DJANGO_SECRET_KEY`.
